# Universe Archive

A holographic universe wiki with a Galactic News Network (GNN) broadcast. It is a static site: plain HTML, CSS and JavaScript with no build step, so it runs directly on GitHub Pages.

## Publish on GitHub Pages

1. Create a new public repository on GitHub (for example `universe-archive`).
2. Upload everything in this folder to the root of the repository: `index.html`, `404.html`, `.nojekyll`, `README.md` and the `assets` folder. Keep the folder structure as is.
3. In the repository, open **Settings > Pages**.
4. Under **Build and deployment**, set **Source** to **Deploy from a branch**, choose the `main` branch and the `/ (root)` folder, then select **Save**.
5. After a minute or two, the site is live at `https://<your-username>.github.io/<repository-name>/`.

Tip: if your file browser hides `.nojekyll`, create it on GitHub with **Add file > Create new file**, name it `.nojekyll` and leave it empty. It tells GitHub to serve the files as they are, without the Jekyll build step.

All paths are relative, so the site works at a project address (`username.github.io/repo-name/`), a user address (`username.github.io`) or a custom domain.

## Shared online storage (everyone sees the same content)

GitHub Pages only serves files, so it cannot store anything. To make articles, star systems, gate lanes, nebulae and chat permanent and the same for every visitor, the site uses **Firebase** (Google's free database service) as its online store. Until you set it up, the site works as before and saves in each browser only.

What is shared once it is set up:

| Content | Who can see it | Who can change it |
| --- | --- | --- |
| Articles | Everyone | Administrator |
| Starmap: systems, lanes, nebulae, states and conditions | Everyone | Administrator |
| Chat (starmap) | Everyone, live | Administrator posts and clears |
| Commanders online | Everyone, live | Any browser logged into a command (heartbeat) |
| Starmap UI: locks, selection, camera, Details panel, dock switches, audio | Stay in each browser (client side) | Each visitor |
| Bookmarks, faction filter, Command Module switch, commander login | Stay personal in each browser | Each visitor |

Map edits and chat messages appear in every open browser within about a second, without reloading. Everything else on the starmap (locks, selection, panning and zoom, the Details panel, dock switches, music and radio) runs only in each visitor's own browser.

### One-time setup (about 10 minutes)

1. Go to https://console.firebase.google.com, sign in with a Google account and select **Create a project** (any name, for example `project-reliquary`). Google Analytics is not needed. The free **Spark** plan is enough.
2. **Database:** open **Build > Firestore Database > Create database**. Choose a location near you and start in **production mode**.
3. **Rules:** in Firestore, open the **Rules** tab. Replace everything there with the contents of `firestore.rules` (your administrator e-mail is already filled in; it must match `adminEmail` in `assets/cloud-config.js`, in lower case) and select **Publish**. Publish again whenever `firestore.rules` changes.
4. **Administrator account:** open **Build > Authentication > Get started**. Under **Sign-in method**, turn on **Email/Password**. Under **Users**, select **Add user** and enter your administrator e-mail and the password you want to type into **Admin login**.
5. **Allow your site:** in **Authentication > Settings > Authorized domains**, add `<your-username>.github.io`.
6. **Web app settings:** open **Project settings** (gear icon) > **General** > **Your apps**, select the web icon (`</>`), register an app (no hosting needed) and copy the values from the `firebaseConfig` it shows.
7. Open `assets/cloud-config.js`, paste `apiKey`, `authDomain`, `projectId` and `appId`, and set `adminEmail` to the same e-mail. Upload the file to GitHub.
8. Open your site, select **Admin login** and sign in with the Firebase password. If this browser already has articles or a starmap, the site asks whether to share them with every visitor. Select **OK** on the main page (articles) and on the starmap (map) to publish what you have built so far.

The sidebar on the main page shows **SHARED ARCHIVE · Shared online · live** when it is working.

### Good to know

- The values in `cloud-config.js` are meant to be public; the database rules are what stop visitors from changing anything.
- With shared storage on, the administrator password is the Firebase password, checked by Google rather than in the page. To change it, use Firebase Authentication > Users > Reset password.
- Each browser keeps a copy of the shared content, so the site still shows the last version it saw if the connection drops. The first time shared content replaces a browser's own articles or map, that browser keeps its old copy as a backup.
- The free plan allows 50,000 reads and 20,000 writes per day. Each visit reads only a few records, so this is plenty for a personal site.
- Keep using **Export JSON backup** (main page) and **Export** (starmap) now and then for your own copies.

## Administrator mode

Visitors can read, search and bookmark articles, but creating, editing, deleting and importing articles requires administrator mode. Select **Admin login** at the top right of the page and enter the administrator password. While signed in, the button reads **Admin · Log out** and the New article, Edit article, Delete article and Import controls appear. Administrator mode lasts until you log out or close the browser tab.

With shared online storage set up, the password is your Firebase administrator password and is checked by Firebase; the database itself refuses changes from anyone else. Without it, the password is checked in the browser against a SHA-256 hash: a deterrent rather than true security, since everything is saved in each visitor's own browser. Choose a password you do not use anywhere else.

## Starmap

The Starmap section on the home page opens `starmap.html`, a full-screen galactic chart.

- Move with W, A, S, D (or the arrow keys); hold Shift to move faster. Zoom with the mouse wheel, Q and E, or the + and − buttons. Drag empty space to pan. The ⌂ button resets the view.
- The background is a procedurally generated field of stars until a background image is supplied. To use an image, add it to the repository (for example `assets/starmap/background.jpg`) and set `BACKGROUND_IMAGE` near the top of the script in `starmap.html`; `BACKGROUND_BOUNDS` sets the map area it covers.
- The **Details** panel (turned on and off with the Details button) lists every star system; select one to fly to it and see its notes and gate lanes.
- Admin login uses the same password as the main page, and signing in on one page carries over to the other in the same browser tab. Administrators get map tools: **＋ Star system** (click empty space to place one), **⟷ Gate lane** (click one system, then another; keep clicking to chain lanes; Esc or right-click stops), and **Select / move** (drag systems to reposition them). Select a system or lane to rename it, add notes, or delete it (Delete key also works).
- Gate lanes show animated ship traffic: small specks of light travelling in both directions, warm-white one way and pale blue the other, fading in and out at each end. Select a lane to see its traffic level (1 = quiet, 10 = busy); administrators adjust it with the Lane traffic slider, which updates the map immediately and saves when released. New lanes start at 5. Reduced-motion settings show the traffic as still specks. Administrators can also set each lane's condition: Open (blue), Caution (yellow, traffic cut to half) or Closed (red dashed line, no traffic). Caution and Closed lanes are labeled on the map and in the panels; the traffic slider keeps its setting, so reopening a lane restores it. Traffic scales steeply: level 1 is a lone ship on a typical lane, 5 is a steady trickle, and 10 is a dense stream of about 50 ships, with busier lanes glowing more brightly. Ships travel slowly, taking roughly 20 to 50 seconds to cross a typical lane. To keep the map fast, traffic is shown in full at 1x zoom and closer; zooming out steadily reduces the number of ships and dims them. One zoom step in from the farthest zoom (about 0.2x), each lane shows 1 ship at traffic 1 rising to 4 ships at traffic 10. At the farthest zoom (0.15x), traffic is hidden and the animation stops.
- Each star system is drawn as a realistic star with a bright core, soft halo and diffraction spikes. New and existing stars default to 8-point Classic at Medium size. In admin mode, the gear button in a system's panel opens a star appearance menu with Shape (8-point, 4-point, 6-point, Round), Design (Classic, Bright, Dim, Ringed with an orbital ring, Binary with a companion star), Size (Small, Medium, Large, Huge) and Color: Red, Green, Blue, Yellow, White and Purple, each in three shades (Light, Standard, Deep; for White: Pure, Warm, Cool), plus the default blue-white.
- Administrators can add **nebula clouds** with **☁ Nebula**: click the map to place one (click a star to center it on that star). Each nebula is a large, transparent, glowing cloud drawn beneath the gate lanes and stars. Its panel has Shape (Billowing, Wispy, Ring or Patchy), a Reshape button that generates a new random cloud in the same shape, Size, Stretch, Rotation and Density sliders, and a main and accent color from ten choices (Crimson, Rose, Ember, Amber, Gold, Emerald, Teal, Azure, Violet, Dust) that blend across the cloud. A name is optional. While a nebula is selected, drag it to move it; Delete removes it. Star systems inside or near a nebula light it up in their own star color, fading with distance (`NEB_LIGHT` and `NEB_LIGHT_STRENGTH` in `starmap.html` set how far and how strongly). Visitors see the nebulae; clicking inside one shows its name and the star systems within it, and named and unnamed nebulae are listed under the star systems in the panel. Nebulae are saved and exported with the rest of the map.
- **Locks** (admin toolbar) protect parts of the map from accidental edits. Lock or unlock Systems, Gate lanes and Nebulae individually, or use Lock all / Unlock all. A locked kind cannot be placed, moved, edited or deleted, and locked nebulae also cannot be selected (clicks pass through them to the map, and they are left out of the panel's nebula list): its toolbar button is greyed out, its panel shows the read-only view with a lock notice, and dragging it does nothing (the map pans instead). System state (Peace, Instability, Conflict, At War) and lane condition (Open, Caution, Closed) are not covered by the locks and can always be changed, including the automatic switch of connected lanes to Caution when a system enters Conflict or At War. Import is disabled while anything is locked. The button shows how many kinds are locked. Everything is locked by default: all three kinds start locked whenever the starmap loads and whenever you sign in as administrator, so unlock only what you need. Unlocks last until the page is reloaded or you sign in again (locks are a per-browser editing aid and are never shared).
- Administrators can set each star system's state from its panel: Peace (normal blue-white), Instability (yellow), Conflict (orange) or At War (red). A colored ring around the star and the system's label show the state (the star keeps its own color), and non-peaceful states are tagged in the Systems list. Visitors see the state but cannot change it. New systems start at Peace. Setting a system to Conflict or At War automatically switches every lane connected to it to Caution, except lanes that are already Closed; new lanes drawn to such a system also start on Caution. Returning a system to Peace or Instability does not reopen its lanes, so set those back to Open by hand. In admin mode, each gate lane listed in a system's panel has a condition dropdown (Open, Caution, Closed) for changing that lane without selecting it on the map.
- **Sound** (top bar, available to every visitor, not just administrators) has two separate buttons, **Music** and **Radio**, both off each time the map opens. Music plays a slow space-ambience score (drifting synth pads, a deep drone and occasional chimes, generated in the browser, with no noise or static layer). Radio plays gate-traffic chatter. Each button shows its own volume slider while it is on, and the sliders remember their settings. A light on the Radio button pulses while someone is transmitting, and sound pauses while the tab is in the background.
- The chatter is 38 recorded exchanges (160 lines) centred on gate clearance: ships requesting approval to enter a numbered gate, giving clearance codes and calling in as they exit a gate; controllers asking where they are headed and what their business is; pilots answering (cargo runs, passenger liners and sightseeing tours, convoy, diplomatic and medical escorts, couriers, crew transfers, mining, salvage, survey, pilgrims, patrols); and controllers clearing, queuing or redirecting them. The lines use the names of the star systems currently on the map (Test, Test Two, Test Four, Test Five, Gallia, Zirndorfia, These Stars and With Gate Lanes) rather than faction names; they are fixed in the recordings and will be re-recorded once the final system names are decided. Three Azure neural voices are used: Luna (Singapore English, female), Guy (slightly deep male) and Brian (lighter male). **Each exchange is a conversation between two of them that keeps the same two voices from start to finish**: the caller (the one who opens the hail) speaks every one of their lines in one voice and the other party answers in another. Voices change only when a new hail starts, and the caller's voice rotates from one exchange to the next. Every line has a radio filter built into the recording (narrow radio band, mid-range bump and light distortion), so it sounds the same in every browser, and transmissions have soft key-up and release tones; there is no added static or interference. Caution, closed-lane and wartime exchanges play only rarely unless the map has caution or closed lanes or systems in Conflict or At War, and recent exchanges are not repeated. Near the audio section of `starmap.html`, `AUDIO_DEFAULTS` sets the sliders' starting volumes and `MUSIC_MAX` and `RADIO_MAX` set how loud each gets at full slider. The sliders change the level directly; only a peak limiter sits on the final output.
- The recordings are in `assets/radio/radio-data.js`: the three voices' MP3 audio (radio filter applied) stored inside a script file, plus the list of exchanges and where each line sits. Storing them this way means the radio works on GitHub Pages and also when `starmap.html` is opened straight from disk. The file loads only the first time Radio is turned on. If it is missing, the Radio button turns itself off and a message says to upload it.
- With shared online storage set up, every map edit by the administrator is saved online and appears for every visitor straight away. Without it, map edits are saved in your browser; to publish them, use **Export** to download `starmap-data.json` and replace that file in the repository. `starmap-data.json` is also what visitors see before anything has been shared online. **Import** loads an exported file back in (and, with shared storage on, shares it).



Visit the published GitHub Pages address, or open index.html in a modern browser. No installation, account, or build step is required. To use it offline, download the whole folder and keep index.html and the assets folder together.

## Accounts

Visitors can create an account to post on the Message Board. The **Sign in** button in the top bar (on the main page and the Message Board page) opens the account window:

- **Create account:** a username (3 to 20 letters, numbers, - or _) and a PIN (6 to 12 digits), entered twice. The window warns, in a highlighted box: use a username and PIN that you do not use anywhere else, and never reuse a bank card PIN, a phone PIN, or any password or username from another site or account. A forgotten PIN cannot be recovered (an administrator can delete the account so the person can make a new one).
- **Sign in:** username and PIN. Members stay signed in on that browser until they sign out.
- **Account** (click your name in the top bar while signed in): set a **display name** (2 to 30 letters, numbers, spaces, or . _ ' -), shown on your posts and in Online now, and **Sign out**.
- **Administrator:** while signed in as administrator, the button reads **Accounts** and lists every member (display name, username, date joined) with **Delete**. Deleting asks for confirmation and then whether to delete that member's posts too. A deleted account can no longer sign in or post. Its username stays reserved; to free it completely, also delete the user `u.<username>@reliquary.example.com` in Firebase console > Authentication.
- Accounts use Firebase Authentication (the PIN is the password, handled by Google; it is never stored in the site's database) and the `users`, `usernames`, `banned` and `online` collections. They need shared online storage, the **Email/Password** sign-in method enabled in Firebase Authentication (already on for the admin login), and the latest `firestore.rules` published. Only one person can be signed in per browser tab: signing in as administrator signs a member out, and the other way round. The code is `assets/accounts.js` (window) and `assets/cloud.js` (storage).

## Message Board

- **Main page:** a **Message Board** banner (just under the Commander's Briefing, or the Restricted access panel when Command Module α is off) opens `board.html`. It shows **Online now** (the display names of members who are signed in and have any site page open; updated live, a member drops off about two minutes after closing the page) and **New posts, last 24 hours** (the four newest topics and replies with who posted and how long ago, plus a count).
- **Message Board page (`board.html`):** uses the full width of the window, with Online now at the top and the forum below it. A **My Characters** button in the top bar, next to the account button, opens the Characters pages (it is highlighted while you are there); the trail at the top of each page (Forum › …) leads back to the forum. Every page has its own address (`#forum`, `#board-general`, `#topic-…`, `#characters`, `#character-…`), so pages can be bookmarked or shared and the browser's Back button works; **Home** returns to the main page.
- **Forum sections and boards:** the forum is divided into sections that collapse and expand when you click the section header (remembered in this browser). The **OOC** (out of character) section holds four boards: **Rules & Getting Started**, **General**, **Memes** and **Off-topic**. **OOC boards have no topics:** each board is one running thread, and you write straight into it with the message box at the bottom (posts run oldest to newest, and the board opens at the newest). The forum page shows each OOC board's description, number of posts and who posted last. Only the administrator posts in Rules & Getting Started. Topics posted before this change appear in General in date order with their title in bold above the first post, and links to them from the main page jump to that post. Below OOC is the **Roleplay** (in character) section, with **one board per sector** (star system) on the starmap, listed alphabetically with the sector's state (if not at peace) and the first line of its notes. The list is read live from the shared starmap, so placing a new system in the starmap creates its board automatically, and renaming it renames the board. If a system is removed from the map, its board stays listed as "Removed sector" while it still has posts. Roleplay boards work like a classic forum: anyone signed in can start a topic (**New topic**) and reply. A sector's board id is `sec-` plus the system id (`sectorBoardId` in `starmap.html` and `board.html`). Boards in other sections keep topics unless they are marked `flat`. Sections and boards are the `FORUM` list in `board.html` (`flat: true` on a section or board makes it topic-free); adding a board there needs no rule change, but add its name to `BOARD_NAMES` in `index.html` so the main-page banner can name it.
- **Context Menu:** a panel down the right side of the Message Board page. The **»** button collapses it to a small **ⓘ** tab on the right edge (click it to open the panel again); open or collapsed is remembered in this browser, and the tab shows a red dot when you have unread messages. On phones and narrow windows the panel slides over the page. It has three tabs:
  - **Characters:** a search box (by any name, race, occupation, nationality, affiliation, other details, player or background; matches highlighted) and the list of characters. Clicking any character anywhere on the page (a post's picture or name, a quoted portrait, a character card or a list entry) shows their **bio** in the panel instead of opening a page: portrait, name, player, details and background, with **Edit** on your own characters and **Message [player]** on other people's. The **×** closes the bio. If the panel is collapsed it opens. (Ctrl+click still opens the character's full page.)
  - **Online:** the members online now (with the count on the tab). Click someone to message them.
  - **Messages:** private messages between members. The list shows one conversation per person (newest first, with the last message and a red dot for unread ones); the tab shows how many are unread. Click a conversation to read it (this marks it read) and reply in the box at the bottom. Hover over a message for its actions: your own messages have **Edit** (Enter saves, Esc cancels; edited messages show "edited") and **Delete** (removes it for both of you); a message you received has **Delete** (removes it from your inbox only). **Delete conversation** at the top removes the whole conversation from your inbox only (Enter sends, Shift+Enter starts a new line, up to 1,000 characters). **New message** lets you pick any member. If received or sent messages cannot be loaded (for example before the latest rules are published), the Messages tab shows the problem and keeps retrying every 15 seconds, so it recovers without a reload once the rules are fixed. Only the sender and the recipient can read a message, not even the administrator; messages are stored in `messages` in Firebase. The administrator account can send and receive messages too, as "Administrator": signing in as administrator registers the account (`admins` in Firebase), after which members can reply to it and find **Administrator** under New message (it does not appear in Online). A member account you use yourself (for example SysAdmin) is a separate inbox from the administrator's. If a conversation partner is not in the member list yet, the page checks the account directly before saying it no longer exists.
- **Characters:** the My Characters page lists your characters and everyone else's. Anyone signed in (member or administrator) can create up to **ten characters** (`CHAR_MAX` in `assets/cloud.js` and `board.html`, and the `_([1-9]|10)` in the `characters` rule). Each character has a numbered **slot** (1 to 10, shown as Alt+1 … Alt+0 on its card); a new character takes the first free slot. Characters belong to the account that made them: the quote buttons above a message box show only the signed-in account's characters, so characters made while signed in as administrator do not appear when you post as a member account (for example SysAdmin). A message box with no characters shows a short note linking to My Characters. **Give to member** (administrator only, on each of the administrator's own character cards) moves a character to a member account you pick: it takes that member's first free slot, keeps its picture and details, shows in their quote buttons and hotkeys, and leaves the administrator account. Quotes in posts written before the move still show as bold speech in quotation marks, but without the portrait. **New character** opens a form with an image (**Upload image**, resized in the browser to at most 400 pixels and stored as a small JPEG, or **an https image link**), up to four names (first name required, middle, last and other name), basic information (date of birth, place of birth, gender, height, weight, nationality, race, occupation and affiliation; free text up to 60 characters, so in-setting dates and units work) and a background (up to 8,000 characters). Click a character to see its profile (picture, details, background and who plays it). On your own characters, **Edit** and **Delete** are on the card and the profile; the administrator can delete any character. Deleting a member's account also deletes their characters.
- **Posting:** posts go under your own display name (posts made earlier as a character still show that character's picture and name); posts show a lettered tile. Signed-in members post under their display name (coloured amber, blue or Republic blue if they are also logged into Eisdon, Gallia or Secaran Republic command); the administrator posts as "Administrator" (sign in as administrator on the main page, then open the board in the same tab). **New topic** asks for a title (up to 120 characters) and a message (up to 2,000); each topic has a reply box. Visitors see "Read only. Sign in or create an account to post."
- **Character quotes:** once you have a character, the message box has a **Quote** row with a button for each of your characters (picture and first name). Click a character and everything you type is that character's speech: it shows bold and in quotes as you type, and the button stays lit. Click the button again to stop (or click another character to switch). **Hotkeys:** Alt+1 to Alt+9 and Alt+0 do the same for the character in slots 1 to 10 (each Quote button shows its number), from anywhere on the page while a message box is showing; the caret goes back to where you were typing. (On a Mac use Option. Some browsers on Linux use Alt+number to switch tabs and keep it.) Selecting some text first and clicking a character turns that text into their speech. In the post the speech shows bold in quotes, with no "says" label; **hovering** over it (or tapping it) shows the speaking character's portrait and name; move the mouse up onto the portrait and click it (or the name) to show the character's bio in the Context Menu. Only your own characters can be quoted; if a character is later deleted, its speech stays bold without the portrait. Enter starts a new line and Ctrl+Enter posts. Quotes are saved in the post text as `[q=character id]…[/q]`.
- **Deleting:** members can delete their own replies, and their own topics if no one else has replied; the administrator can delete any reply or topic.
- Posts are stored online (`board` in Firebase) and update live. Firebase checks that each post's author name matches the signed-in member's display name, or for a character post that the character belongs to the poster and the name matches, so posts cannot be made under someone else's name or character. Characters are stored in `characters` in Firebase (ids are the owner's account id plus 1 to 10, which is what enforces the limit). If a character is deleted, its old posts keep the name without the picture.

## Command Module (alpha)

The first step toward the strategy (RTS) layer. While signed in as administrator on the main page, the **Command Module α** on/off switch in the top bar turns the module on or off for that browser (the switch shows ON in green when it is on). When it is on, the Restricted access panel on the home page becomes the **Commander Login**:

- Choose a command: **Eisdon**, **Histannia** or **Harron**. Only Eisdon is open for now; the other two show "Channel offline".
- Enter the command's access PIN (Eisdon: `1234`, Gallia: `5678`, Secaran Republic: `9012`). PINs are checked against a SHA-256 hash in `index.html` (`CMD_FACTIONS`); like the admin password, this is a client-side gate, not real security.
- After logging in, the panel becomes the **Commander's Briefing**: a dark, riveted metal console with hazard stripes and exposed cabling, and a green holographic terminal showing the command's **treasury credits** (0 CR for now) and **current events** (none yet). Its side plate shows uplink status and has **Tactical starmap** and **Log out** buttons. A control strip below has knurled rotary knobs with scale rings (Gain, Freq, Band), red flip toggle switches with indicator lamps (Uplink, Scan, Aux), a reactor gauge and status lamps; they respond to clicks but are decorative for now.
- While logged in as the Eisdon commander, the starmap switches to the **Eisdon industrial interface**: dark steel toolbar with a hazard stripe and cables hanging beneath it, riveted metal panels, beveled steel buttons, a green holo HUD and terminal-style inputs. In this interface, **Music**, **Radio** and **Details** are rugged red toggle switches (a red lever on a hex nut, screwed to a steel plate) that flip up for on and down for off, with green-screen labels that glow when on, and each volume control is a knurled rotary knob with a scale ring that stays on the console even while its music or radio is off (set the level before switching on) (drag up or right to turn it up, or use the mouse wheel or arrow keys). The **Details** switch flips the sector panel open on a hinge and powers on its green screen, which shows the selected system, lane or nebula; switching it off flips the panel shut. Reduced-motion settings skip the animation. Under the title, an "Eisdon Command" badge shows which command you are logged into, with a **Change Command** button: it opens a screen to log out of the current command and then log in to another (pick a command and enter its PIN). Logging out, or turning the module off, returns the starmap to the standard look. The command list and PINs are kept in both `index.html` and `starmap.html` (`CMD_FACTIONS`); keep them in step.
- While logged in as the **Gallia** commander, the starmap switches to the **Gallia interface**, which is separate from Eisdon's: a clean dark-grey brushed-steel toolbar (fine horizontal brushing with a soft highlight) and a blue light strip beneath it, brushed-steel-framed panels with blue display screens, and practical steel push buttons. **Music**, **Radio**, **Details** and the dock switches are push buttons with a backlit lens that lights blue when on, next to a blue display label; each volume control is a digital meter (a segmented blue bar with a numeric readout) that you adjust by dragging left or right, the mouse wheel or the arrow keys. The Details panel and dock panels slide out and their displays power on with a scan line (skipped with reduced-motion settings). The badge reads "Gallia Command" and Comms is labelled "Gallia command net". On the main page the Gallia commander's briefing uses the same look: dark-grey brushed steel, a blue display, digital readouts instead of knobs, illuminated push buttons instead of toggles and a digital reactor meter. With **Music** on, Gallia has its own soundtrack instead of the space ambience: a slow, noble French horn theme in E-flat major (60 BPM). ## Saving and backups

With shared online storage set up (see above), articles are stored online and shared with every visitor, and only bookmarks stay in this browser. Without it, edits and bookmarks are stored in this browser's local storage, not written into index.html. Browser storage for local files can vary by browser. Keep the same file location and browser profile; moving the file, changing browsers, using private browsing, or clearing site data may make saved entries unavailable. If storage is blocked or full, the app warns you; export before closing.

Use Import / export > Export JSON backup regularly. To move to another computer, copy index.html and your exported JSON file, open the app, and import the backup. Imports replace all current articles and bookmarks after confirmation. Export your existing archive first. Deleting an article also removes its bookmark and incoming related-entry references. Imported content is treated as text, not executable HTML.

The app starts empty, ready for your own universe. On the first load after this update, unedited bundled articles from the previous version are removed from browser storage, along with their bookmarks and related-entry references. Articles you created or edited are preserved. The internal storage key remains unchanged so existing custom work can be retained. Later imports and edits are retained across reloads when local storage is available.

Without shared online storage, there is no cloud synchronization: the app only loads its own files and sends no data anywhere, and saved articles live in each visitor's own browser. With it, the app also loads Google's Firebase library and reads and writes your own Firebase project; nothing is ever written into the repository. Editing related-entry relationships or explicit system coordinates requires editing a JSON backup and importing it.
